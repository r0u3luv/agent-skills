# PR Triage

Build a concise picture of a pull request before implementation or review work.

## Workflow

1. Identify the stated goal and linked issues.
2. Summarize changed areas by module or feature.
3. Highlight risky files, migrations, public APIs, or shared utilities.
4. List what reviewers should inspect first.
5. Capture verification status and obvious gaps.

## Output

Return:

- Scope
- Risk areas
- Review order
- Verification status
- Open questions
